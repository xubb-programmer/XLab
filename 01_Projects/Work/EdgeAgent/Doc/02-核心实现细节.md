# 核心实现细节

## 启动、线程与停止

[main.cpp](../EdgeAgent/src/main.cpp) 初始化日志，按 `--config`（`-c`）、`EDGEAGENT_CONFIG`、可执行文件所在目录的 `config.json` 依次选择配置。`loadConfig()` 校验失败时记录 `configuration_error` 并以退出码 2 退出。正整数 `--run-for-ms` 用于定时退出。

[EdgeAgent.cpp](../EdgeAgent/src/EdgeAgent.cpp) 按校验后的配置创建通道和设备映射，先启动通道，再启动 MQTT。单个通道启动失败时会记录故障，其余通道和 MQTT 继续启动。退出时先停止通道，再请求 MQTT 断开并停止网络线程。Broker 侧状态见 [03 配置与接口契约](03-配置与接口契约.md)。

通道和协调器在 Qt 主事件循环中运行。libmosquitto 在独立网络线程收消息，将 Topic 和正文复制后通过 Qt 信号交给主线程。连接成功后重新提交设备命令订阅，并发布保留状态 `online`。MQTT 重连由 libmosquitto 管理，延时参数为 1 至 60 秒，启用指数退避。收到 `online` 后可结合通道日志和实际数据判断现场侧是否就绪。

## 上行分帧

[FrameCodec.cpp](../EdgeAgent/src/FrameCodec.cpp) 实现 TCP 和串口共用的 `FrameDecoder`。每条 TCP 连接有独立缓存，采用空闲分帧时也有独立定时器。串口使用自己的分帧器和定时器。

| 模式 | 帧何时完成 | 上报字节 |
| --- | --- | --- |
| `delimiter` | 找到完整分隔符，可跨多次读取，单次读取可拆多帧 | 分隔符之前的字节 |
| `fixed_length` | 缓存达到配置长度，尾部不足一帧时留待下一次读取 | 固定长度的全部字节 |
| `length_prefix` | 读满 1、2 或 4 字节长度头后，再等齐声明的正文字节 | 正文，支持长度为 0 的帧 |
| `idle_timeout` | 有数据时重置定时器，到达静默间隔后取出非空缓存 | 当前缓存的全部字节 |

`max_bytes` 限制帧正文。分隔符模式允许未完成的缓存额外保留至多「分隔符字节数减一」个字节，空闲模式直接限制缓存大小。分帧错误会中止对应 TCP 连接，或关闭串口并安排重开。TCP 断开时丢弃该连接未完成的帧。

收到完整帧后，通道生成 `FrameEvent`，记录此时的 Unix 毫秒时间。协调器先记录接收日志，再按设备绑定编码并尝试发布。UDP 和 CAN 直接使用自身报文边界。

## 下行路由与回执

1. `EdgeAgent::onMqttMessage()` 检查 Topic 结构、运行状态及设备绑定，按通道类型调用 `decodeSendRequest()`。
2. 接收标记为 retained 的命令走 `retained_command` 回执分支。其余命令继续检查解析结果和串口或 CAN 的本地端点。
3. 通道处理目标选择和写入。TCP 统一命令只允许唯一连接，UDP 同时检查白名单与大小限制。
4. `encodeSendResult()` 生成 `sent` 或 `failed` 回执，尝试以 QoS 1 发布。通道拒绝写入时，回执代码统一为 `send_failed`，具体原因见通道故障日志。

UDP、TCP 和串口用写入接口返回的字节数判断成功，CAN 使用 `writeFrame()` 的返回值。TCP 和串口的写入可能先进入 Qt 的发送队列。代理按收到的命令直接提交字节，设备事务、发送重试和去重由调用方管理。

## 连接恢复

| 接口 | 当前实现 |
| --- | --- |
| UDP | 启动时绑定本地地址，按配置加入组播。绑定或入组失败记录故障，需修正条件后重启 |
| TCP 服务端 | 开始监听后接收新连接，超出 `max_clients` 拒绝接入。监听失败需修正条件后重启 |
| TCP 客户端 | 按配置控制连接超时，断开或连接失败后退避重试，成功后重置退避 |
| 串口 | 打开失败、分帧错误或需要重开的 I/O 错误触发退避重试。超时、校验、帧格式、Break 和不支持的操作错误只记录故障 |
| CAN | 通过 Qt SerialBus 创建配置指定的后端。打开失败、连接或读取错误以及设备断开时重试。写入错误记录故障，错误帧及非法帧不上报 |

TCP 服务端使用 `server-<UUID>`，客户端使用 `client-<UUID>`。重新接入或重连会获得新的 ID，统一命令按当前连接表匹配。

## 日志

[Logging.cpp](../EdgeAgent/src/Logging.cpp) 用 spdlog 输出单行 JSON。普通事件写标准输出，故障写标准错误，两者同时写入轮转文件。默认文件是可执行文件目录的 `logs/edgeagent.log`，可通过 `EDGEAGENT_LOG_FILE` 覆盖。单文件 10 MiB，最多保留 5 个历史文件。

| 事件 | 可查看的信息 |
| --- | --- |
| `agent_starting` | 网关 ID、运行时通道数和设备绑定数 |
| `channel_state`、`fault` | 通道状态、故障代码及原因 |
| `rx` | 通道、传输类型、连接 ID、时间、字节数和完整 HEX 正文 |
| `mqtt_connected`、`mqtt_disconnected`、`mqtt_fault` | Broker 连接状态与错误 |
| `mqtt_data_not_published` | 数据上报未被 MQTT 客户端接受 |
