# 扩展开发与迁移

## Linux / WSL 构建

主程序使用 C++17 和 qmake。需要 Qt 5 的 Core、Network、SerialPort、SerialBus 模块，以及 libmosquitto、spdlog、fmt、nlohmann/json 的开发包。Ubuntu 可使用下列包名。最后三个包提供联调和自动化测试所需的 Broker、MQTT 客户端和 Python。

```bash
sudo apt update
sudo apt install build-essential qt5-qmake qtbase5-dev \
  libqt5serialport5-dev libqt5serialbus5-dev \
  libmosquitto-dev libspdlog-dev libfmt-dev nlohmann-json3-dev \
  mosquitto mosquitto-clients python3
```

使用 SocketCAN 时还需安装 `libqt5serialbus5-plugins`，并在 Linux 中准备并启用相应接口。

从同时包含 `Doc`、`EdgeAgent`、`EdgeAgentTester` 的项目目录执行构建。子 shell 结束后会回到原目录。

```bash
mkdir -p EdgeAgent/build-proxy
(
  cd EdgeAgent/build-proxy &&
  qmake ../EdgeAgent.pro &&
  make -j4
)
```

Qt Creator 可打开 [EdgeAgent.pro](../EdgeAgent/EdgeAgent.pro)。Windows 原生构建需要匹配的 Qt Kit、编译器、头文件及链接库，工程的 Windows 编译选项使用 MSVC 风格。串口名按本机配置，例如 `COM3`。CAN 后端取决于已安装的 Qt SerialBus 插件及硬件驱动。

图形测试工具使用独立的 [EdgeAgentTester.pro](../EdgeAgentTester/EdgeAgentTester.pro)，生成 `edgeagent-tester`，可模拟现场端的 UDP、TCP、串口和 CAN。它有独立的 TCP/串口分帧设置和发送封装选项。使用相同的换行分帧与默认 TCP 服务端联调时，测试工具中的分隔符输入 `\n`。

## 本地启动与 UDP 双向联调

在同一个 Linux / WSL 环境使用监听 `127.0.0.1:1883` 的 Broker。若该地址尚无 Broker，可在单独终端启动本地实例。下列配置只监听回环地址。

```bash
(
  broker_conf=$(mktemp) || exit 1
  trap 'rm -f "$broker_conf"' EXIT
  printf 'listener 1883 127.0.0.1\nallow_anonymous true\npersistence false\n' > "$broker_conf"
  mosquitto -c "$broker_conf"
)
```

在项目目录启动代理。配置路径是相对当前目录解析的。需要限时冒烟运行时，可追加 `--run-for-ms 5000`。

```bash
./EdgeAgent/build-proxy/edgeagent --config EdgeAgent/config.json
```

启动后观察 `channel_state` 和 `mqtt_connected` 日志。另开终端订阅 UDP 上行和回执。

```bash
mosquitto_sub -h 127.0.0.1 -p 1883 -q 1 -v \
  -t 'edge/v1/devices/plc_udp_dev/data' \
  -t 'edge/v1/devices/plc_udp_dev/command-results'
```

保持订阅运行，在另一个终端模拟现场端。脚本从 `127.0.0.1:19090` 发出四个字节，并通过 MQTT 请求代理向这个端口回送两个字节。

```bash
python3 - <<'PY'
import socket
import subprocess

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as peer:
    peer.bind(("127.0.0.1", 19090))
    peer.settimeout(5)
    peer.sendto(bytes.fromhex("01020304"), ("127.0.0.1", 18080))
    subprocess.run([
        "mosquitto_pub", "-h", "127.0.0.1", "-p", "1883", "-q", "1",
        "-t", "edge/v1/devices/plc_udp_dev/commands",
        "-m", '{"id":"udp-smoke","data":"A1B2","meta":{"endpoint":{"address":"127.0.0.1","port":19090}}}',
    ], check=True)
    payload, source = peer.recvfrom(65535)
    assert payload == bytes.fromhex("A1B2"), payload.hex()
    print(source, payload.hex().upper())
PY
```

订阅终端应看到 `data` Topic 上的 `"data":"01020304"` 和 `command-results` 上的 `{"id":"udp-smoke","status":"sent"}`。脚本应输出 `('127.0.0.1', 18080) A1B2`。若代理记录 `udp_bind_failed` 或 `tcp_listen_failed`，先检查配置端口和占用情况。若回执是 `send_failed`，可从通道 `fault` 日志查找具体原因。

## 从现有配置迁移

1. 保留 v1 时，继续在每个通道中声明 `device_id`，按需填写 `qos` 和 `message_format`。迁移 v2 时，将这三项移到 `devices` 的对应项，保留原 `device_id`，并填入原通道的 `channel_id`。将 `config_version` 设为 `2`。
2. 保留旧上行或旧回执的消费者时，为相应绑定显式设置 `"message_format":"legacy"`。接入统一格式的消费者时，按 [03 配置与接口契约](03-配置与接口契约.md) 更新解码和回执关联。
3. 在统一的 `channels` 列表调整地址、白名单、接口名和分帧参数，通过 `enabled` 切换模板。验证禁用模板的参数和设备引用，重启后查看启动日志中的通道数及绑定数。
4. 部署时使用 `--config` 或 `EDGEAGENT_CONFIG` 显式指定文件，也可将其命名为 `config.json` 放在可执行文件旁。qmake 工程只将仓库配置列为分发文件，运行前需确认实际加载的文件位置。

## 扩展入口

通过现有通道接入设备时，由业务服务编码完整发送字节，订阅 `data` 解析设备报文，并按协议判断响应。TCP 和串口的分帧配置只作用于接收方向。

增加物理接口时，从 [Channel.h](../EdgeAgent/src/Channel.h) 的接口开始，实现启动、停止、发送和接收事件。把配置解析接入 [Config.cpp](../EdgeAgent/src/Config.cpp)，在 [EdgeAgent.cpp](../EdgeAgent/src/EdgeAgent.cpp) 装配通道，在 [TransportCodec.cpp](../EdgeAgent/src/TransportCodec.cpp) 补充对应的元数据编解码与校验，再验证目标定位、故障恢复和回执。MQTT Topic 和发布继续由协调器管理。
