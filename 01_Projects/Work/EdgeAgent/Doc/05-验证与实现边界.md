# 通信代理：验证与实现边界

## 1. 验证入口

Linux/WSL 从项目根目录执行：

```bash
python3 EdgeAgent/tests/run_tests.py
```

入口构建 EdgeAgent.pro 和 tests/TransportTests.pro，执行组件测试及本地 MQTT 集成验证。构建输出位于 EdgeAgent/build-proxy，编译日志保存在 build.log 和 tests/build.log。

## 2. 组件测试

- 原始 TCP/串口二进制正文保持不变，结构化 HEX 和 connection_id 解析。
- JSON 字段类型、无效操作、HEX、正文大小及 UDP 地址/端口校验。
- CAN 标准/扩展 ID、RTR、DLC、负载长度和字段类型检查。
- 四种分帧：半帧、合并帧、跨读取分隔符、大小端长度及缓存上限。
- v1/v2 配置、透明声明兼容、重复绑定和无效字段拒绝。
- 真实 TCP 回环：首次连接拒绝后重连成功，双向字节收发。
- 统一 config.json 通过实际解析器加载；默认仅启用两个通道，开启全部模板后六个通道及设备绑定均可加载。
- v1/v2 通道开关、布尔类型、禁用模板参数校验、禁用通道及其 Topic 绑定排除。
- 四类通道采用相同上行信封和 endpoint.address 结构；上行可复用为回复，CAN 数据帧/远程帧往返编解码。
- meta、endpoint、connection、frame 的类型、适用性、端口/长度边界及新旧字段混用校验。
- 统一格式默认值、显式 legacy 兼容、时间戳和消息 ID 校验及简洁发送回执。

## 3. MQTT 集成测试

使用临时本地 Broker、真实 UDP/TCP socket 和 Linux 伪终端串口，验证：

- retained 命令拒绝，物理接口未收到下行。
- v1 UDP 上行元数据、二进制载荷、定向下发及目标白名单。
- v1 TCP Server 半包/粘包、原始/HEX 发送、错误参数及不存在的连接拒绝。
- v2 TCP Client 长度前缀分帧、统一 HEX 信封和端点/连接定向回复。
- v2 串口空闲分帧、统一端点、接口约束及旧原始下行兼容。
- 统一 UDP 端点往返、错误 meta 拒绝、新旧格式下行兼容。
- 统一 TCP Server 多客户端上报、按连接/端点回复、目标不唯一和端点/连接矛盾时拒绝。
- TCP 客户端重连及服务端连接替换均产生新的 connection，旧连接标识不可误投到新会话。
- 关闭的 TCP 通道即使配置了与启用通道相同的端口，也不会绑定该端口或订阅命令。
- 发送回执仅使用 sent/failed。

仅清理测试创建的子进程、伪终端和临时文件，不访问现场设备。

## 4. 实现与验收边界

| 能力 | 当前状态 |
|---|---|
| UDP/TCP/串口/CAN 透明收发 | 已实现 |
| TCP/串口四种接收分帧 | 已实现 |
| 连接重连、白名单、日志和 MQTT 状态 | 已实现；UDP 绑定失败不会自动重试 |
| 设备报文解释、轮询及业务缓存 | 由上层业务服务负责 |
| 持久化补发、命令去重、配置热更新、TLS | 未实现 |
| CAN FD | 不支持 |
| 正常停止主动发布 offline | 未实现；当前仅配置异常断线遗嘱 |

伪终端不覆盖真实 RS-485 电气质量、收发方向切换、USB 延迟和拔插行为。CAN 通过编译和参数测试不等同于真实总线验收；接口比特率及 Bus-Off 恢复需外部设置。

发送 sent 只代表本地接口接受数据，MQTT 发布成功也不代表业务方处理完成。队列持久化和设备业务执行确认需在系统层面另行处理。

当前自动化测试不提供 Windows 原生构建、实际 CAN/串口硬件或长期性能验收结论。
