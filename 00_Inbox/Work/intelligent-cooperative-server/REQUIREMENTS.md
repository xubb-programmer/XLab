# 当前需求

本阶段包括在线设备发现、角色分类、经纬高配置和无人机视频展示，以及地图目标展示与目标报文上报。

## 在线设备发现与角色分类

1. **自动发现**。EdgeAgent 监听 [组播设备状态协议](../multicast-device-status-report.md) 的 IPv4 UDP 报文，平台通过 MQTT 主题 `edge/v1/devices/device-status-device/data` 接收转发结果。兼容协议 2.0 与旧版扁平 JSON。收到有效报文后按设备 ID 显示，使用硬件序列号区分同 ID 的设备。设备默认进入在线无人机列表。
2. **角色与挂载**。设备默认进入监测席列表；操作员可将设备标记为独立作业单元，或将其挂载到场景点位。监测席与作业单元视图不互斥，挂载设备仍保留在监测席并继续提供视频、坐标和飞机轨迹；同一设备最多挂载一个点位。已设为独立作业单元的设备须先取消独立标记才能挂载。发现 ID 冲突时提示核对设备并暂停该 ID 的分类。
3. **状态更新**。两个列表使用同一份 EdgeAgent 转发状态。默认 5 秒没有收到新报文时判为离线，监测席、独立作业单元和已挂载点位均保留并标记离线。新版报文的快照时间过旧时单独提示。
4. **数据范围**。设备发现、角色和坐标由设备台账管理，仅用于卡片展示、分类和视频访问。目标上报使用单独配置的场景点位。

## 目标上报至作业单元

目标上图和向作业单元上报均经过 EdgeAgent。接收后的处理由接收端负责。

1. **网页操作**。选中目标后点击「下派任务」，分配点位并确认。Node.js 读取目标坐标并按点位配置的 EdgeAgent 设备 ID 路由，省略设备 ID 时使用点位编号。
2. **报文发送**。Node.js 通过 MQTT 把报文交给 EdgeAgent。EdgeAgent 通过 TCP 发送以 LF 结尾的 UTF-8 JSON。报文的 `name` 固定为 `Action`，`params` 包含十进制度经纬度 `lon`、`lat`，米制高程 `elevate`，以及发送时换算的米制高斯坐标 `x`、`y`。
3. **结果显示**。Node.js 通过 MQTT 按设备 ID 和 `request_id` 匹配 TCP 应用回执。匹配的回执返回布尔值 `ok: true` 时确认成功。发送后超时显示「上报结果未知」。
4. **批次和重试**。服务端先校验所有指派。超过任一点位 `maxTargets` 时整批拒绝。同一设备串行发送，链路异常、超时或接收端忙时暂停该设备，其余设备继续。批次和逐条结果存入 SQLite。重复提交同一批次返回已有状态，差量重试使用服务端保存的坐标与指派，仅处理已确认可重试的记录。结果未知由操作员核实，设备解除暂停后才可继续。

## 本阶段移除或暂不实现

- 无人机巡航速度、机头航向及航向罗盘、剩余电量均暂不能提供，直接移除对应字段和控件。原「视轴定位无人机与目标」按钮也移除。
- 地面作业单元不展示初始速率、资源储备和部署状态；不显示设定目标、执行或模拟执行按钮。
- 移除演示坐标、计划航线、演示目标与视频，以及场景目标操作、暂停数据流、单步采样等演示控件。地图初始视角的配置只用于定位视图。
- 不显示执行参数、轨迹或复核解算。接收端坐标格式确认前不做坐标转换。

## 接入状态与待办

1. **设备状态**。已通过本地 EdgeAgent 自测协议 2.0 和旧版组播状态报文转发、在线发现、角色切换、离线标记和手动经纬高保存。实际设备的组播接口和源地址仍需现场核对。
2. **现场配置**。按需填写场景 JSON、视频 JSON 和 MQTT 代理地址及认证信息。部署时确认设备台账的存储路径与访问范围。
3. **目标上图联调**。Qt 模拟器发送的 033（1501）监测目标已通过本地 EdgeAgent 和 MQTT，到达网页目标接口。现场需用实际设备报文验证。
4. **作业单元上报联调**。已有网页上报按钮、点位设备 ID 配置以及 MQTT 和 EdgeAgent 转发。用模拟接收端验证协议后，再与外部接收端联调。
5. **视频与位置联调**。已在原网页验证组播发现设备的视频播放和通道切换。监测席经纬高由操作员设置。载荷实时位置读取组播的 `飞机位置`，地图支持独立显示载荷和目标。现场需验证实机连续上报。
