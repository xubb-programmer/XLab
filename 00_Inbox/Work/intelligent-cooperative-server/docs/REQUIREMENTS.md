# 单兵作战协同平台 · 业务需求与技术实现规格书

本文档系统性定义并记录单兵作战协同平台当前的业务需求、系统架构、交互标准与实际代码实现状态。

---

## 一、系统定位与运行环境

1. **系统定位**：面向便携野战平板、车载显控端及后方指挥所大屏的一体化态势协同显控与数据中枢。
2. **核心目标**：实现无人机/监测设备在线发现、多源态势目标动态上图、作业单元编制架构与打击任务协同下派。
3. **脱网运行保障**：全系统（前端页面、离线地图切片、SVG 矢量图标库、轻量数据库与服务端）支持 100% 脱离公网运行。
4. **硬件与部署基准**：
   - Linux 嵌入式板端：RK3588 平台（Ubuntu 22.04 LTS，系统服务 `intelligent-cooperative-server.service`）；
   - 客户端：Windows 电脑显示器（桌面指挥端）与触控平板电脑（便携终端）。

---

## 二、界面多端自适应与触控交互规范

系统全面适配**大屏电脑显示器（信息高密度）**与**平板电脑（触控便携、有限视野）**，杜绝地图挤压或界面溢出。

### 1. 分辨率分层断点与布局行为

| 屏幕形态与尺寸 | 核心布局模式 | 侧边栏与地图行为 | 触控与交互规范 |
| :--- | :--- | :--- | :--- |
| **电脑宽屏显示器**<br>`> 1280px` | 经典三栏平铺布局 | 左右侧边栏固定平铺展开；三维地图居中自适应伸缩，视野宽阔。 | 键鼠精细化操作，支持悬停高亮与快捷键。 |
| **平板电脑横屏**<br>`1024px ~ 1280px` | 紧凑布局 / 视野优先 | 顶栏单行紧凑自适应，地图 100% 铺满；侧栏默认紧凑折叠，点击拉手平滑展开。 | 触控热区放大，地图支持单指平移、双指缩放与俯仰旋转。 |
| **平板电脑竖屏**<br>`≤ 1024px` | **全屏地图优先 + 悬浮抽屉遮罩 (Drawer Overlay)** | 地图视口保持 100% 铺满；左右侧栏转为**悬浮抽屉**（`position: absolute; z-index: 25; backdrop-filter: blur(16px)`），**两抽屉互斥折叠**。 | **拉手随动吸附**：展开抽屉时拉手吸附于抽屉外沿，手指单手轻触即可快速关闭。 |
| **触控优化模式**<br>`@media (pointer: coarse)` | 触控防误触与热区增强 | 侧边折叠拉手热区扩大至 `54px ~ 58px`；按钮最小点击区域扩大至 `≥ 36px ~ 38px`。 | 避免细小操作点，表单控件间距自动扩增。 |

### 2. 视口与引擎感知实现

1. **动态视口高度（`100dvh`）**：全局容器与视图采用 `100dvh` 与 `flex: 1; min-height: 0;`，彻底解决平板移动浏览器地址栏唤出/收缩时的底部溢出与白边滚动问题。
2. **画布重绘防抖监听**：针对平板横竖屏旋转（`orientationchange`）和窗口拖拽调整（`resize`），内置 120ms 防抖自动调用 Cesium 引擎 `viewer.resize()`，确保三维视锥比例精确。
3. **表单网格自适应折叠**：设置卡片坐标网格在竖屏下由 3 列自动转为响应式流动网格，弹窗最大宽度限制为 `95vw` 并配备独立滚动条。

## 三、视觉风格与交互细节标准

### 1. 矢量 SVG 图标体系（100% 离线规范）
- 导航栏、左右侧栏、地图核心工具条、台账列表、模态弹窗全面适配矢量 SVG 图标；
- 统一图标规格：`viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round"`，与地图“引导线开关”风格严格统一；
- 采用深色半透明玻璃拟态质感（`rgba(8, 14, 22, 0.9)` + 高斯模糊），高亮态采用天青色（`#00f0ff`）或警戒红（`#ff4757`）。

### 2. 专业简洁的界面文字体系
- **去刻意化与工程用语**：剔除所有刻意、生硬的“战术”字样（如：“三维视角”、“数据链状态”、“初始地图位置”、“数据管理”）；
- **导航精炼**：顶部主导航分别为「综合态势」、「火力挂载」、「侦察车智能助手」、「即时通讯」、「情报辅助分析」（已去除冗余“系统”二字）、「设置」；
- **设置卡片精炼**：彻底删除了卡片和台账条目下的小学生式长句副标题描述，隐藏底层技术存储文件路径，整体清爽直观。

### 3. 板块标题自定义与全局实时双向同步
- **双向就地编辑**：在左侧栏板块头部或设置台账卡片内，均提供 **修改图标 [✎]**，同时支持**双击标题直接重命名**；
- **全链路自动同步联动**：当任一侧修改时，系统通过 `setCustomTerm` 实时联动更新左侧栏、顶栏统计项、设置台账名称（自动拼接“台账”二字）及数据管理分类标签；
- **双重持久化**：本地写入客户端 `localStorage`，同时向服务端 `/api/terms` 发送持久化请求，写入板端 `config/terms.json`，重启不丢失。

## 四、轻量化统一数据库架构（SQLite 单库多表）

系统重构了早期分散在多个文件的数据库设计，采用标准化单文件 SQLite 数据库（`dev_01/operational.db`），由 `server/db.mjs` 集中管理。

### 核心数据表设计与业务关联

1. **设备状态台账表 (`devices`)**：
   - 记录网络中通过 EdgeAgent 发现的设备，涵盖设备 ID、硬件序列号、通信 IP、角色标记（监测席 / 独立作业单元）、在线状态与最新心跳时间戳；
2. **作业单元阵位表 (`firepower_points`)**：
   - 维护作战阵位点位配置，涵盖点位 ID、名称、经纬度、高程、打击射程半径（km）、所属营连架构及绑定的设备 ID；
3. **态势目标记录表 (`targets`)**：
   - 存储接收到的态势目标与炸点轨迹，记录目标编号、类型（监测目标 / 告警事件）、位置坐标、历史轨迹点序列与更新时间；
4. **协同上报批次表 (`report_batches`)**：
   - 记录态势目标分发下派至作业单元的任务批次、裁决分配方案、分发下发状态及执行回执；
5. **席位配置表 (`recon_seats`)**：
   - 记录监测席位编号、通道映射与关联 RTSP 视频流地址；
6. **建制架构表 (`org_structure`)**：
   - 维护“指挥所 ➔ 营 ➔ 连”多级树形名录编制与点位归属关系。

## 五、在线设备发现与协同业务流程

### 1. 设备发现与状态管理
1. **组播协议自发现**：EdgeAgent 监听组播设备状态 IPv4 UDP 报文（`239.255.0.1:5678`），平台通过 MQTT 主题 `edge/v1/devices/device-status-device/data` 接收转发。系统放开静态白名单限制，支持局域网任意有效单播 IPv4 设备即插即用自动纳管。
2. **设备保活与离线判定**：默认 5 秒内未收到新报文时判定为离线，界面保留该节点并标记为离线状态。
3. **席位与单元挂载**：设备默认进入监测席列表；可标记为兼任作业单元或挂载至特定阵位点位。

### 2. 南向边缘通信网关与网络自适应规范 (EdgeAgent)
1. **态势上报触发控制指令 (UDP 28081)**：
   - 全面收敛至 EdgeAgent 代理下发（MQTT 主题：`edge/v1/devices/target-input-device/commands`，信封携带 `transport: "udp", endpoint: { address, port: 28081 }`）；
   - **智能同网段回传自适应**：下发指令中的 `上报地址`（`reportHost`）自动计算并优先使用本机与目标设备同一子网的真实物理网卡 IP（如目标为 `192.168.0.x` 则自动回传 `192.168.0.201`，为 `192.168.10.x` 则自动回传 `192.168.10.201`），彻底杜绝开发机静态 IP 导致的回传数据黑洞；
   - **手动单播 IP 兜底机制**：当网络环境禁用组播或交换机阻断时，操作员可在监测席配置中手动输入单播 IP，系统优先采纳手动 IP 直接下发态势触发指令。
2. **目标上图与协同分配下发 (TCP 5567)**：
   - **目标报文接收**：接收 ScoutMonitor `cartype=033（1501）` 协议报文，由 EdgeAgent 监听 UDP 28080 并经 MQTT 推送至平台动态标注上图；
   - **协同指派与多方案裁决**：系统内置射程包络与负载容量计算算法（`allocation-strategy.js`），支持“就近分流”、“最优推荐”与人工裁决分配；
   - **打击指派下发**：按批次生成报文，经由 EdgeAgent 代理建立 TCP 链路下发至目标火力单元；
   - **前置防呆校验**：若被指派火力点的通信 IP 仍为本地回环（`127.0.0.1`）且未挂载真实设备，系统在提交时自动弹出前置拦截提示，避免盲目发送导致超时。
3. **板端双物理网口（eth0 / eth1）盲插冗余保障**：
   - RK3588 板端 `eth0` 与 `eth1` 均已配置统一的静态业务 IP（`192.168.0.201/24` 及 `192.168.10.201/24`），现场网线插拔切换任一网口均可无感接入，保障系统持续可用。

## 六、部署与交付验收标准

1. **Linux 板端部署**：
   - 部署路径：`/opt/jw/intelligent-cooperative-server/current/web/`
   - 服务管理：`systemctl restart intelligent-cooperative-server.service`，确保状态为 `active`；
2. **文件完整性与一致性**：
   - Windows 本地与 Linux 实体板端的核心代码、配置及样式文件需保证 MD5 校验 100% 一致。
3. **现场验收检查项**：
   - 访问地址：`http://<IP>:4177/`；
   - 态势数据链状态显示为 `● 已订阅`；
   - 电脑大屏（1080p）与平板电脑（iPad Air / 1024×768 / 768×1024）自适应渲染工整，抽屉与把手触控顺畅。
